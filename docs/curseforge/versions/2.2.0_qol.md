<h2>v2.2.0 - Invalid JAR Fix + Config Files Moved</h2>

<h3>Fix</h3>
<ul>
<li><strong>Critical</strong>: 2.1.2 shipped an invalid <code>neoforge.mods.toml</code> — the build script's version-templating step mangled a <code>\n</code> line break inside the <code>credits</code> field into a raw newline, which is illegal inside a single-line TOML string. The loader rejected the JAR entirely ("not a valid mod file"), so 2.1.2 did not load anywhere, client or server. Fixed at the build level.</li>
</ul>

<h3>Change</h3>
<ul>
<li>The mod's config files now live at <code>config/utility_core/utility_core_qol-common.toml</code> and <code>config/utility_core/utility_core_qol-client.toml</code> instead of directly in <code>config/</code>, grouping them with the other Utility Core mods (Admin, Fixes).</li>
</ul>

<blockquote><strong>Breaking</strong>: if you're updating from an earlier version, your existing configs at <code>config/utility_core_qol-common.toml</code> / <code>config/utility_core_qol-client.toml</code> are <strong>not</strong> migrated automatically. They stay on disk (orphaned) and new configs with default values are generated at <code>config/utility_core/</code>. Copy your settings (including Bridging Assist) over manually if you want to keep them.</blockquote>
