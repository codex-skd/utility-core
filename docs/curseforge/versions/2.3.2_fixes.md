<h2>v2.3.2 - Curios Loot Predicate Crash Fix</h2>

<h3>Fix</h3>
<ul>
<li><strong>Server crash on entity death when a Curios item is enchanted</strong>: Curios injects a mixin into vanilla's <code>NbtPredicate.getEntityTagToCompare</code> that merges the entity's Curios inventory into the NBT being compared for loot table / advancement predicates. When any equipped curio is enchanted, serializing that NBT needs access to the <code>minecraft:enchantment</code> registry, which is not accessible in this evaluation context and throws <code>IllegalStateException: Can't access registry ResourceKey[minecraft:root / minecraft:enchantment]</code>. This was uncaught and crashed the server (<code>Ticking entity</code>) whenever a loot table condition evaluated an <code>EntityPredicate</code> against an entity carrying an enchanted curio — e.g. any player death loot table.</li>
<li>Added a mixin on the vanilla <code>LootItemEntityPropertyCondition.test</code> that catches this <code>IllegalStateException</code> around the predicate check and fails the predicate instead of propagating the crash.</li>
<li>New config toggle <code>enableCuriosLootPredicateFix</code> (default <code>true</code>) to disable this behavior if needed. Requires Curios to be present to matter, but does not hard-depend on it.</li>
</ul>
