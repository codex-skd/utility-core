<h2>v1.11.5 - Recipe Selection Lock Fix</h2>

<h3>Fix</h3>
<ul>
<li><strong>Recipe selection reverting to first option after clicking</strong>: When clicking a recipe variant in the selector, the selection would change momentarily but then automatically revert to the first option. The issue was caused by a server-side race condition: when the server processed the selection click, it would re-execute the recipe calculation logic, but the stored recipe list in <code>PlayerRecipeData</code> wasn't being reinitialized if the crafting inputs hadn't changed since the last calculation. This caused the selection to fail validation and reset to the first recipe. The fix ensures the recipe list is always properly initialized when processing multiple recipes, even during selection updates.</li>
</ul>

<h3>Technical Changes</h3>
<ul>
<li><code>MixinCraftingMenu.onSlotChangedCraftingGrid()</code> &mdash; added check to ensure <code>data.setRecipes()</code> is called when the recipe list is empty, even if inputs haven't changed. This guarantees <code>PlayerRecipeData</code> always has the current recipes before validating any selection.</li>
<li><code>PolymorphClientHandler.receiveServerRecipes()</code> &mdash; improved safety check: only reset <code>selectedIndex</code> if it's actually out of bounds or the recipe list is empty, preserving the user's selection when valid.</li>
</ul>
