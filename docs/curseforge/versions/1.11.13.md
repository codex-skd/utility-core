<h2>v1.11.13 - Recipe Selector Stops Being Cleared</h2>

<h3>Fix</h3>
<ul>
<li><strong>Recipe selector stops being wiped by the inventory menu</strong>: The selector still failed to respond — clicks registered client-side, but the server rejected them because its recipe cache was constantly emptied. The player's inventory menu (<code>InventoryMenu</code>) stays subscribed to inventory changes even while another menu is open, so every inventory change re-ran <code>slotChangedCraftingGrid</code> with the empty 2×2 grid. That fired the "no recipes" branch, which cleared the player's recipe data and sent empty sync packets, hiding the selector and making the click invalid.</li>
<li>The recipe calculation now only processes the player's <b>active</b> container menu (<code>menu == player.containerMenu</code>), so background inventory updates can no longer clear the crafting table's selection. The selection now persists until the player actually changes the ingredients.</li>
</ul>

<h3>Technical Changes</h3>
<ul>
<li><code>MixinCraftingMenu.onSlotChangedCraftingGrid</code> — early return unless <code>menu</code> is the player's current <code>containerMenu</code>, preventing the background <code>InventoryMenu</code> (a permanent listener on <code>PlayerInventory</code>) from clearing the crafting state.</li>
</ul>

<h3>Notes</h3>
<blockquote>Diagnosis: the <code>[RecipeSelector]</code> logs showed <code>slotChangedCraftingGrid: recipes=0</code> being emitted constantly while the crafting table was open (with <code>inputs=4</code> syncs), confirming the 2×2 inventory grid — not the 3×3 table — was the source of the clearing.</blockquote>
