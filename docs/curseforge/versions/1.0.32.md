<h2>v1.0.32 - Ender Dragon Respawn: Crystal Placement Fix with beamTarget</h2>

<h3>Fix</h3>
<ul>
<li><strong>Ender Dragon respawn con YUNG Better End Island</strong>: Los cristales colocados por c&oacute;digo no ten&iacute;an <code>beamTarget</code>, que YUNG requiere para detectarlos (lo mismo que hace <code>ItemEndCrystal.useOn()</code>). Ahora cada cristal tiene <code>setBeamTarget(bedrockPos)</code>.</li>
<li><strong>Posiciones cardinales</strong>: Se usa la distancia 3 en ejes cardinales (N/S/E/W) que funciona en la isla de BEI, eliminadas las diagonales que no tienen bedrock ah&iacute;.</li>
</ul>

<h3>Technical Changes</h3>
<ul>
<li><code>EnderDragonRespawnHandler</code> — cada <code>EndCrystal</code> se crea con <code>setBeamTarget(bedrockPos)</code> replicando <code>ItemEndCrystal.useOn()</code></li>
<li>Eliminados m&eacute;todos redundantes de colocaci&oacute;n diagonal</li>
<li>Si YUNG presente: coloca cristales + llama <code>advanceRespawnStage(START)</code></li>
<li>Si YUNG ausente: coloca cristales + <code>fight.tryRespawn()</code> vanilla</li>
</ul>
