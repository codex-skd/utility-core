<h2>v2.3.3 - Vehicle Anti-Cheat Whitelist Rework for 26.2</h2>

<h3>Fix</h3>
<ul>
<li><strong>Vehicle anti-cheat whitelist was silently not working on 26.2</strong>: the fix intercepted <code>isVehicleMovingTooFast</code> and <code>checkVehicleMovement</code> in <code>ServerGamePacketListenerImpl</code>, but those methods were removed in 26.2 — the <code>moved too quickly</code> vehicle check is now inlined inside <code>handleMoveVehicle</code> as <code>if (movedSqr - velLenSqr &gt; 100.0 &amp;&amp; !isSingleplayerOwner())</code>. The mixin targets no longer matched, so the whitelist never applied.</li>
<li>Rewritten as a scoped <code>@Redirect</code> on the single <code>isSingleplayerOwner()</code> call site inside <code>handleMoveVehicle</code>: when the player's root vehicle is whitelisted it returns <code>true</code>, skipping the check for that vehicle. Other call sites of <code>isSingleplayerOwner()</code> (player movement checks, difficulty/gamemode permission checks) are untouched.</li>
<li>Mixin <code>defaultRequire</code> restored to <code>1</code>: the redirect target was verified against <code>minecraft-server-patched-26.2.0.45-beta.jar</code>, so a future mapping change will fail loudly at startup instead of silently disabling the fix.</li>
</ul>
