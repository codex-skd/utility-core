<h2>v1.11.6 - Recipe Selection Persistence Fix</h2>

<h3>Fix</h3>
<ul>
<li><strong>Recipe selection automatically reverting to first option</strong>: When you clicked a recipe variant in the selector, it would immediately revert back to the first option. The root cause was that processing the selection click on the server side triggered an additional recalculation of the recipe list via <code>menu.slotsChanged()</code>, which would re-execute the entire crafting grid validation logic and reset the selection. The fix removes this unnecessary call, allowing the selected recipe to persist once the user makes their choice.</li>
</ul>

<h3>Technical Changes</h3>
<ul>
<li><code>SelectRecipePacket.handle()</code> &mdash; removed the call to <code>menu.slotsChanged()</code> that was causing a re-execution of <code>MixinCraftingMenu.onSlotChangedCraftingGrid()</code>. The packet now applies the recipe selection directly via <code>setRemoteSlot()</code> and syncs to the client without triggering validation logic again.</li>
<li>Added debug logging when a recipe is selected, showing the recipe name and index in the server log for troubleshooting.</li>
</ul>
