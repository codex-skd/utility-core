<h2>v1.6.1 - Fix: Wrong Blocks in Legacy .schematic Mapping</h2>

<h3>Fix</h3>
<ul>
<li><strong>Wrong blocks when pasting legacy <code>.schematic</code> files</strong>: <code>LegacyBlockMap</code> fed the full legacy metadata value into the variant lookups instead of masking the variant bits. Blocks with extra metadata bits (logs and log2 with axis bits, slabs with the top-half bit, double plants with the upper-half bit, monster eggs and skulls with high bits) resolved to the wrong block — e.g. a stone slab placed as quartz, or an oak log as jungle. The variant index is now masked correctly (<code>data &amp; 7</code> / <code>&amp; 3</code> / <code>&amp; 1</code>) so the palette maps to the intended block.</li>
</ul>

<h3>Technical Changes</h3>
<ul>
<li><code>LegacyBlockMap#toState</code> — masked variant bits in <code>pick()</code> for planks, saplings, logs, log2, leaves, stone/wood slabs, monster eggs, skulls and double plants.</li>
</ul>

<h3>Notes</h3>
<blockquote>Applies only on a brand-new world. For an existing world, delete the world save folder and regenerate it.</blockquote>
