<h2>v1.10.0 - ChunkGen: no keepAlive, 100 chunks cap</h2>

<h3>Breaking Changes</h3>
<ul>
<li><strong>Removed <code>chunkGen.keepAlive</code></strong>: the idle-pause workaround was unreliable (it could not locate the server pause field in every version). To keep generating while the server is empty you must now disable the empty-server pause: set <code>pause-when-empty-seconds=-1</code> in <code>server.properties</code>. Without it the server pauses after 60s idle and generation freezes.</li>
</ul>

<h3>Improvements</h3>
<ul>
<li><strong><code>chunkGen.chunksPerTick</code> hard cap = 100</strong>, enforced in code (config range 1-100; previous cap was 300). Generating at 300 chunks/tick left the server at near-zero TPS during pregeneration, stalling logins and world download. Default is now 100; values 1-8 are recommended to keep the server responsive.</li>
</ul>

<h3>Config</h3>
<ul>
<li><code>chunkGen.keepAlive</code> &mdash; removed.</li>
<li><code>chunkGen.chunksPerTick</code> &mdash; range 1-100 (hard cap in code), default 100.</li>
</ul>

<h3>Technical Changes</h3>
<ul>
<li><code>ChunkGenManager</code> &mdash; removed <code>keepAlive()</code> and the tick-field reflection; clamped <code>chunksPerTick</code> to 100.</li>
<li><code>Config</code> &mdash; removed <code>CHUNK_GEN_KEEP_ALIVE</code>; <code>chunkGen.chunksPerTick</code> max 100; config comments now document the <code>pause-when-empty-seconds=-1</code> requirement.</li>
</ul>

<h3>Notes</h3>
<blockquote>Server operators: after updating, set <code>pause-when-empty-seconds=-1</code> in <code>server.properties</code> and restart. Configs with <code>chunksPerTick &gt; 100</code> are clamped by code.</blockquote>
