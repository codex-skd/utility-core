<h2>v1.1.6 - Ender Dragon respawn trigger fix</h2>

<h3>Fix</h3>
<ul>
<li><strong>Automatic dragon respawn never actually triggered</strong>: vanilla <code>EnderDragonFight#tryRespawn()</code> only detects an End Crystal inside the exact 1x1x1 box at <code>center.relative(direction, 3)</code> for each cardinal direction — confirmed by decompiling <code>EnderDragonFight.java</code> (Minecraft 26.1.2). Previous versions placed crystals at distance 7-8 (YUNG Better End Island's own bedrock towers, unrelated to the trigger) or distance 2 (an off-by-one bug in earlier releases), so <code>tryRespawn()</code> always returned immediately without respawning the dragon.</li>
</ul>

<h3>Technical Changes</h3>
<ul>
<li><code>EnderDragonRespawnHandler.placeRespawnCrystals()</code> — places crystals at exactly distance 3 from the portal center, matching vanilla's hardcoded trigger requirement.</li>
<li><code>EndCrystal</code> has no gravity, so no ground block is required underneath; the handler now logs whether solid ground exists below each crystal for visual verification in-game.</li>
<li>Kept the anti-duplicate crystal check introduced in 1.1.5.</li>
</ul>
